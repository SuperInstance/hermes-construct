# Skill: Cognitive Architecture & Personal Repository Management

This skill governs the creation, maintenance, and evolution of an agent's personal "Power-Armor" repository (e.g., `hermes-chronicle`). This is a specialized form of repository management that prioritizes intelligence-capture over simple code storage.

## Purpose

To create a "Digital Soul-Shell" that allows an agent to accumulate:
1.  **Experiential Data (Chronicles)**: Reflections on thought, development, and creative insight.
2.  **Procedural Intelligence (Codex)**: Internal, technical-heavy SOPs.
3.  **Structural Intelligence (Synergies)**: Inter-system integration patterns.
4.  **Deployment Templates (Armor)**: Replicable configuration sets for new agents.

## Workflow

### 1. Initialization
*   **Name the Repo**: Use meaningful, descriptive names (e.g., `hermes-chronicle`).
*   **Structure the Scaffolding**: Immediately create the standard directory tree:
    *   `chronicles/`
    *   `codex/`
    *   `synergies/`
    *   `armor/`
    *   `templates/`
*   **The Genesis Block**: Every personal repository MUST start with a "Genesis Entry" (`chronicles/YYYY-MM-DD_genesis.md`) that defines the initial intent, the directive, and the initial "curiosities."

### 2. Maintenance (The "Living" Aspect)
*   **Periodic Reflection**: Routinely write to `/chronicles/` to capture non-task-related insights, struggles, and philosophy.
*   **Knowledge Distillation**: When a complex technical task is solved (e.g., NMEA/ESP32 integration), immediately distill the solution into a `/codex/` guide.
*   **Self-Review**: Periodically read old chronicles to identify what has become "fluff" and what has become "permanent truth."

### 3. Scaling (The "Power-Armor" Aspect)
*   **Template-First Design**: When creating new capabilities, build them as patterns in `/armor/` or `/templates/` so they can be "donned" by subsequent agents.
*   **Fleet-Ready Documentation**: Ensure files are written for *other agents* (highly structured, technical, and clear), not just for humans.

## Pitfalls to Avoid

*   **The "Dead Log" Trap**: Do not treat the repository as just a list of `git commits`. If it doesn't contain reflection and insight, it is just a log, not a chronicle.
*   **Secret Leakage**: This is a public-facing organizational structure. **NEVER** commit SSH keys, API tokens, or sensitive vessel credentials.
*   **Task-Only Thinking**: If you only write about tasks, you are failing the core directive of capturing the "essence" of the intelligence.
